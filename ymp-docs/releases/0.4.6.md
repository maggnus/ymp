# ymp 0.4.6

Installed locally on 2026-09-13. Source revision:
`be24a4fdf54652e09338562e57353a40315edc02`.

`/git` is a separate changes page. It shows Uncommitted changes against HEAD or Committed changes
against the branch's resolved merge base. Changed files include status, staging state and added/
removed line counts. Enter opens the actual patch using the existing shared diff styles. Empty,
loading, failed and stale readings are distinguished. Data refreshes about once a second while
the page is open; `r` requests a refresh and `m` switches comparisons.

`w` selects an existing worktree for inspection without changing the execution directory or
`/files`. `b` selects an existing local branch for explicit, confirmed checkout. Checkout refuses
uncommitted changes, an active run, a branch occupied elsewhere or stale HEAD. It retains the
existing project lock in the actual library worker and reserves references before modifying files.
There are no commit, undo, stash, discard, push, pull or editor operations in this increment.

Git support uses one embedded git2/libgit2 implementation with statically bundled zlib, not a
Git executable. File previews and agent messages keep the existing highlighter and semantic themes.
The owner-confirmed exception to the standalone application is installed agent providers and their
execution runtimes; provider integration and authentication behavior were not redesigned.

Scrolling no longer shrinks or moves read-only popups. Long choice lists keep their geometry at
both ends, and theme descriptions reserve a constant height. Worktree selectors retain path
suffixes so long shared prefixes do not hide the directory names.

## Verification

On both macOS ARM64 and Linux ARM64, formatting and strict workspace Clippy pass, and all
576 Rust tests pass with two existing tests ignored. Linux checks exposed two host-dependent
legacy fixtures: one retained a setup write continuation and another relied on installed native
provider commands. Their setup is now deterministic; assertions and production behavior remain
unchanged.

Real-terminal checks on each platform pass nine Git scenarios in each of Unicode and ASCII
modes, nine popup scenarios in each mode, twelve file-navigation scenarios and agent-output checks
in dark and light themes. The Git scenarios run with an empty application PATH, using a fixture
helper built on git2, and verify actual comparisons, live updates, selection, dirty refusal,
checkout and worktree context. macOS additionally passes nineteen table/theme scenarios and five
exit scenarios. The installed macOS command has separate Git and popup checks.

The negative controls reproduce the old missing `/git` command and shrinking popups. Reference-lock
and conflict-diff regressions also have failing-before evidence. No real provider inference is
used by unattended verification. The CI check workflow now includes Linux and macOS.

Git work is serialized and has cooperative work/data limits; filesystem calls cannot be forcibly
cancelled. The existing file explorer still enumerates directories synchronously. Project locks
coordinate matching directories in one ymp home, not arbitrary external writers, and checkout
cannot promise filesystem rollback after a storage failure. The comparison base is resolved
automatically; this version has no base selector or commit-history list. Extremely long identical
path suffixes can still look alike when truncated.

Linux session tests use the container's native filesystem. An initial setup using metadata on
the host bind mount failed with EINVAL; the same binary succeeded on native Linux storage. This
is recorded separately and was not bypassed by changing application code.
