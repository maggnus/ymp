# ymp 0.4.5

Installed locally on 2026-09-13 from source `f29bb7a21b01e29250f1ab27f63eccfcfa8f9e61`.

Agent messages now show language-tagged code with syntax colours directly in the conversation,
in Detailed mode and in Inspect. Explicit `diff`/`patch` blocks and structurally complete raw
unified/Git patches distinguish additions, deletions, context, file names and hunk headers.
An ordinary prose list remains prose. Patch styling describes reported content and makes no
claim that a change was applied or independently accepted.

Code preserves indentation, repeated and trailing spaces and blank lines. Tabs expand to
four-column stops; control characters are written visibly. Matching backtick or tilde fences
close blocks, while unfinished streamed blocks remain open. Stored message bytes and originating
invocation labels are unchanged. The implementation reuses the highlighter introduced in
[0.4.4](0.4.4.md), whose file navigator and eighteen themes remain available.

The presentation decision draws on pinned Gemini CLI, OpenCode and Aider sources in the
[agent-output contract](../architecture/agent-output-highlighting.md). Source changes are tracked
in YMP-140. No storage migration or provider authentication change is required.

## Verification and limits

Formatting, strict workspace Clippy and all 554 Rust tests pass; two existing tests remain
ignored. Independent terminal checks cover inline and Inspect colours in Ember and Catppuccin
Latte, unchanged stored messages and monochrome markers. File navigation passes 12 cases in each
of Unicode and ASCII modes; tables/themes pass 19 cases, and deliberate exit passes five cases.
The installed command is checked separately for colour and monochrome output in both themes.
All unattended checks use local fixtures or scripted providers.

Completed messages receive syntax colours. During streaming, code is shown literally without
syntax highlighting; declared patches retain their line-role styles. Unknown languages and
code beyond the styling limits remain plain and readable. A message admits at most 64 KiB of
code and starts no further block after 250 ms of recorded highlighting cost. A frame starts no
further uncached block after 50 ms. These checks occur between blocks/lines: they do not cancel
a line already parsing, and initial grammar loading is separate. The cache holds at most 1,024
texts and 8 MiB of source; that is not a bound on total process memory.

Directory enumeration remains synchronous and has no timeout or cancellation. Linux and
Windows runtime checks and real-provider inference were not performed. Existing workspace
policy and the absence of universal captured before/after edit content remain unchanged.
