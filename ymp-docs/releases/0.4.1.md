# ymp 0.4.1

This patch corrects recovery from ACP `max_tokens` during independent review.
The runtime distinguishes an incomplete native response from a general failure,
keeps reported usage and permits one fresh read-only review within captured
attempt and resource limits. It preserves the producer's submitted result and
does not change the requested model or effort.

Repeated exhaustion remains incomplete. Cancellation, other native stop reasons
and runtime budget, deadline or output stops do not cause automatic retries.
Each admitted retry receives a separate invocation and new permissions. No
storage migration or native authentication change is required.

See [recovery behavior and the reported poker session](../guides/incomplete-native-review.md)
and [YMP-129](../tasks/README.md#ymp-129) for verification and progress.
