# ymp 0.4.1

This patch corrects recovery from ACP `max_tokens` during independent review.
The runtime distinguishes an incomplete native response from a general failure,
keeps reported usage and permits one fresh read-only review within captured
attempt and resource limits. It preserves the producer's submitted result and
does not change the requested model or effort.

Repeated exhaustion remains incomplete. Cancellation, other native stop reasons
and runtime budget, deadline or output stops do not cause automatic retries.
Each admitted retry receives a separate invocation and new permissions. No
storage migration or native authentication change is required.

See [recovery behavior and the reported poker session](../guides/incomplete-native-review.md)
and [YMP-129](../tasks/README.md#ymp-129) for verification and progress.

## Validation

Both the offline ACP protocol control and the actual Engine recovery control
failed before the correction. Formatting, strict Clippy and all 425 workspace tests pass; two existing
fixture tests remain explicitly ignored. Independent review accepts the corrected
source with no open findings. Cases include successful recovery, repeated
exhaustion, a single allowed attempt, fresh permissions, unchanged settings,
preserved artifacts and prior spend, no writer retry, unrelated stops, actual
cancellation, incomplete usage and token/invocation ceilings.

The installed executable is checked with version/help and a deterministic mock
team run. The unchanged Claude bridge and the original full evaluation suite were
not rerun for this patch. No paid inference was used. Detailed results and exact
source/binary identities are retained in the
[verification record](../research/evidence/native-review-recovery/verification.json).
