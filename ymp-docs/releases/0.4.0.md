# ymp 0.4.0

Status: release preparation. Final versioned verification, independent YMP-121
acceptance and installation are pending. The [delivery plan](../tasks/plan.md)
records current completion; this document does not announce a released build.

## Changes

- Native catalog scans populate selectable agents with the identifiers, names,
  aliases and controls returned by installed providers. Provider identity stays
  separate. Current and historical names/settings use their appropriate records.
- Sessions use bounded teams of agents with distinct starting-roster, fixed-size,
  fixed-roster, eligible-pool and concurrency constraints. Participants propose
  responsibilities and revisions; the runtime validates and commits decisions.
- Independent assignments can overlap when their enforced workspace access
  permits. Conflicting or unbounded access is serialized, and uncertain work is
  inspected before recovery can repeat it.
- Captured resource limits cover admission, context, native controls, deadlines
  and output. Variable assignment reservations preserve review allowances and
  previous spend. Partial usage remains explicit; stopping is the default for
  incomplete accounting under a reported-token ceiling. Bounded continuation
  requires an explicit captured policy.
- Accepted outcomes are retained incrementally. Supported knowledge and qualified
  experience require relevant confirmation evidence; qualitative acceptance stays
  unconfirmed. Evidence-bound corrections preserve predecessors and replacement
  links while excluding superseded claims from current retrieval.
- Existing terminal views expose assignments, decisions, constraints, usage,
  recorded checks, coordination and knowledge provenance. Public local MCP uses
  stdio, permits reads by default and requires `--allow-execution` for execution.
- Typed Rust interfaces support alternate execution, allocation, workspace,
  knowledge and confirmation implementations. Runtime validation remains outside
  replaceable strategies.

## Upgrade and operation

Keep the existing application home, normally `~/.ymp2`. Configuration and stored
records accept additive fields; absent new unknown-usage policy means `Stop`.
Native authentication stays with the installed provider programs.

Use `ymp catalog --refresh` to read native offerings without a model prompt.
Migration preserves actor IDs, explicit settings, instructions and the starting
team. It does not enroll the whole catalog or rewrite historical execution.
`ymp catalog` reads the stored snapshot. Native scans can take the configured
deadline per installation; initial scanning reports progress before the TUI opens.

Run `ymp -C /path/to/work`. For this MVP, outputs are written directly to the
selected directory and application data stays under the metadata home. A private
temporary address alias supports internal sockets when that home has a long path;
the socket itself remains under metadata. No source-tree copy, automatic rollback
or production publication mechanism is promised. Larger-project isolation and
recoverable publication remain YMP-124.

Saved output locations remain attached to their original results. Metadata-only
project relocation moves no files. Resume retains captured policy and accounting,
revokes old execution authority and inspects uncertain effects. A saved native
conversation handle does not restore its former permissions.

The local installation links to this checkout and needs its built Claude bridge.
Paths and the final verification procedure are documented in
[release verification](../guides/release-verification.md).

## Evidence and limits

The universal suite covers four workflow classes and thirteen protocol scenarios
through the actual runtime using scripted providers and independent validators.
It retains raw records, artifacts, source maps, build hashes and failing controls.
Its [independent max review](../../ymp-evals/reports/ymp-126-independent-max-review.md)
accepts the driver; final release evidence will identify the versioned integrated
source and installed binary separately.

Installed-provider compatibility checks performed so far read metadata only.
Scripted results establish runtime behavior, not a measured model-quality gain,
cheaper computation or superiority over one strong agent. Native token accounting
may be partial, and admission allowances cannot prove a hard expenditure ceiling
inside an opaque provider runtime. No currency-cost estimate is presented as
measured expenditure.
