# Native control envelope, without model inference

Prepared on 2026-09-14 for YMP-201. These observations concern configuration,
protocol adaptation, and filesystem enforcement. They are not model measurements,
quality evidence, a quota allocation, or owner approval.

The inspected installation reports `codex-cli 0.154.0`. Its resolved executable
SHA-256 is `4f85982624b3898c8991cb80c0981b2aa71070e3537046c9a95950318a95afcc`.
The experimental schemas were generated by this executable without a model turn;
selected schema hashes and fields are preserved in
[the initial probe](../native-controls-v2/probe.json) and
[the extended probe](../native-controls-v2/probe-readonly.json).

## Controls actually interpreted by this installation

One-off `-c` arguments, `config/read` with a strictly filtered projection, and
thread-scoped `experimentalFeature/list` confirmed disabled `multi_agent`,
`multi_agent_v2`, `agents.enabled`, memories, memory generation, and memory use.
Additional controls disable memory import, hooks, plugins, apps, browser/computer
use, image generation, goals, skill search, shell snapshots, and unbounded
connection retries. Host skill discovery is skipped. The exact frozen set is
`CONTROLS` in [native_controls_probe.py](../../../../ymp-evals/weak-pilot/native_controls_probe.py).

`model/list` reported both `gpt-5.6-luna` and `gpt-6-astra`, including supported
`low`. New probe threads reported `low`. This is native metadata, not evidence of
a billed call or proof of an execution hierarchy. The measured consumer must
still check the model and effort actually sent and observed on each invocation.

`project_doc_max_bytes=0` produced no instruction sources. A positive control
restoring 32768 bytes loaded the artificial workspace `AGENTS.md`. User instruction
contents were not read. The envelope clears inherited `developer_instructions`
at process startup and preserves production `developerInstructions` exactly;
it does not add a competing `thread.config.developer_instructions` value.

Official references describe
[one-off configuration overrides](https://learn.chatgpt.com/docs/config-file/config-advanced)
and the
[configuration keys](https://learn.chatgpt.com/docs/config-file/config-reference).
The local observations, rather than documentation version alone, establish the
applicability above.

## Why the envelope is necessary

The installed schema supports `permissions` in both `thread/start` and
`thread/resume`, mutually exclusive with `sandbox`. Existing production
`ymp_providers` sends `sandbox=read-only` or `danger-full-access`. The documented
[permission-profile precedence](https://learn.chatgpt.com/docs/permissions)
and actual canaries agree: legacy writable access ignores named read denials;
legacy read-only still reads hidden and peer files.

A tested outer `codex sandbox` preserves explicit denials, including a read-only
workspace. However, applying the inner read-only sandbox again on macOS fails
with exit 71 (`sandbox_apply: Operation not permitted`). That outer arrangement
is preserved as exploratory evidence, and is not the selected consumer route.

[codex_envelope.py](../../../../ymp-evals/weak-pilot/codex_envelope.py) is a narrow
stdio adapter around the same installed app-server. It rewrites only
`thread/start` and `thread/resume`: original `sandbox` becomes a generated named
`permissions` profile, and verified controls/profile data are added to `config`.
Prompts, model fields, turn effort, context IDs, all other requests, response bytes,
and usage events are preserved. Unsupported original access values fail before
the thread request reaches the server.

Profiles grant root read for normal tools, grant the exact working directory
read or write according to the original request, and deny the native home and
every explicit protected path. Command network access is disabled. The app-server
host retains its native authentication and state access. `CODEX_HOME` is not
relocated, and credentials are not copied or printed.

## Inherited MCP isolation

Before the working app-server starts, the same envelope runs a metadata-only
`initialize`/`config/read` process with the frozen controls. Only server names
leave the in-memory configuration response. The working process receives a
scalar `mcp_servers.<name>.enabled=false` override for each inherited server.
Neither the full configuration, endpoint values, nor credentials are logged.
Names outside the verified CLI-override spelling are rejected rather than
rewritten. The journal records only the inherited-server count and whether the
explicit current `ymp` endpoint was enabled.

The production suffix may contain exactly its existing five `-c` settings for
`mcp_servers.ymp`: `command`, `args`, `env_vars`, `required`, and
`default_tools_approval_mode`. The envelope accepts these fields without changing
their values and matches them against the duplicate endpoint in the original
thread configuration. It enables only this explicitly supplied current endpoint.
All other explicitly supplied thread endpoints are disabled. A raw request has
no current endpoint and enables none.

The native configuration merger replaces individual thread MCP entries. Adding
an incomplete inherited entry containing only `enabled=false` loses its transport
and fails configuration loading. This real negative control is preserved in
[native-envelope-mcp-probe.json](native-envelope-mcp-probe.json). The final route
uses scalar startup overrides for inherited entries and preserves complete
explicit thread endpoints instead.

[native-envelope-mcp-fixed-probe.json](native-envelope-mcp-fixed-probe.json)
confirms the final route on Codex 0.154.0. Neither of two artificial inherited
MCP servers, including an inherited `ymp`, started during metadata discovery or
raw threads. A separate thread with a complete current endpoint started only
the artificial trusted `ymp` server. No model turn was submitted. Filesystem
canaries and host access to its artificial state also passed in that same run.

The metadata process inherits the provider process group. Terminating the group
under the consumer's shared deadline therefore also terminates discovery; it
does not leave a detached process. Its elapsed time belongs to native execution
overhead, while `initialize` and `config/read` are not model invocations. The
unchanged policy schema and controls remain separate from owner authorization.

## Stable consumer contract

Invoke Python with these arguments before production appends `app-server --stdio`:

```text
codex_envelope.py --policy ABS_POLICY --codex ABS_CODEX --journal NEW_ABS_JOURNAL
```

The trusted policy has exactly this schema:

```json
{
  "schema_version": 2,
  "controls": "the exact CONTROLS object, not this explanatory string",
  "deny_paths": ["/absolute/controller", "/absolute/evaluator", "/absolute/peer"],
  "native_home": "/absolute/native/codex/home"
}
```

The consumer pins the executable, envelope, dependency script, policy, and
manifest hashes; supplies absolute protected paths and a separate exported
workspace; and creates a fresh journal for each process launch. The envelope
refuses policy fields outside this schema, including owner-identity metadata.
Its journal contains only the control projection and hashes, never prompts,
credentials, or raw configuration. Repeated `--codex-arg ARG` supports the
explicitly labelled offline protocol executable. Native measured launches must
have no such arguments; the trusted consumer enforces that distinction.

## Executed canaries and remaining limits

[native-envelope-probe.json](native-envelope-probe.json) records the check through
the actual envelope. Both named profiles deny reads/writes of hidden, peer, and
artificial native-state files. The read-only profile rejects workspace writes;
the writable profile allows them. The real app-server independently created
`state_5.sqlite` in the same artificial state directory that commands could not
read. This separates native host access from model-command access.

The inference-free reproduction is:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 ymp-evals/weak-pilot/codex_envelope.py \
  --probe --codex /absolute/installed/codex --output /absolute/new/probe.json
```

`command/exec` has no thread selector. The probe therefore loads a server copy
of the exact profiles generated for the threads, then sends both thread requests
and standalone commands through the same envelope. Thread metadata confirms the
profile selection. This does not claim that an actual model tool call occurred.

Fifteen offline envelope tests passed after the MCP changes, including an
explicit byte-echo fixture that checks startup disabling and preserves synthetic
turn and usage records. Tests cover duplicate/conflicting current endpoints,
rejection of extra production options, and instruction-field preservation.
No Cargo checks were launched by this subtask.

[Storage metadata](../native-controls-v2/storage-probe.json) shows that
`sqlite_home`, `log_dir`, and `history.persistence=none` do not move the reported
native session path. `thread/start.ephemeral=true` reports no path, but would lose
continuation when the per-turn process exits. The selected named-profile route
instead denies the existing native-home subtree to commands, while leaving native
host persistence intact. Only newly created artificial contexts were inspected
and deleted; no existing history or credentials were read.

Overrides of `model_providers.openai.request_max_retries` and
`stream_max_retries` failed native startup because the built-in provider ID is
reserved; [safe diagnostics](../native-controls-v2/retry-parse.json) retain no
raw stderr. Absolute transport retry suppression is not a prerequisite. The
consumer must account for reported work, reject unknown/partial usage, enforce
its shared deadline and admission limits, and describe in-flight token overshoot.
Hard billed-token ceilings and real execution behavior remain unverified until
separate owner authorization permits the preparation calibration.
