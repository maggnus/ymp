## Product findings

The pair used one broad write-capable task and completed without task retries.
Opus first rejected the plan and induced stronger shuffle checking. This is a
useful criticism-to-change chain. No invocations overlapped, so faster completion
does not demonstrate useful parallelism or self-organization.

The run still exposed evidence-quality limits. Browser work remained executor-
owned while the independent reviewer read source. A claimed CSS repair was not
supported when pre/post versions were measured under the same viewport. One
responsibility proposal became stale without affecting admitted work. All ten
knowledge retrievals were empty; an overbroad procedural lesson was rejected,
which supports integrity but not later-task learning value.

The comparison strengthens two planning rules: treat model capability and
decomposition as explicit experimental factors, and attribute results only at
the level actually varied. It does not justify always choosing one task, always
using stronger models, or removing independent review.
