# Explicit continuation with incomplete native accounting

The unchanged restart scenario exposed a policy gap after a real process crash. With the default policy, the seed process produced and independently confirmed the workshop document using 40 controlled units, then persisted seven partial units and an incomplete totals file before SIGKILL. A new OS process revoked the previous grant, rejected its actual capability, and attempted Engine recovery. Review admission returned `unknown_usage` at 47 reported units out of the captured 100; no inspection invocation started.

Before evidence: `/tmp/ymp126-restart-stop-second-20260912/restart-inspection`, including `before-crash-runtime.json`, `runtime.json`, `processes.json`, `boundary-result.json` and both native journals. The earlier `stop-first` control had an adapter selection mistake (matching a task name in historical plan context) and is not the claimed exact scenario; it remains retained. The corrected adapter selects the current assignment section.

`ResourceLimits.unknown_usage` is a captured typed policy with `Stop` as the deserialization/default behavior and an explicit `BoundedNative` option. Only the incomplete-accounting admission stop is conditional. The latter option admits against reported spend and live reservations, while the reported-token ceiling, review protection, invocation count, concurrency, context, native-loop, output and timeout limits remain applicable. Unknown measurements stay unknown, partial calls remain partial, no spend is refunded, and `strict_token_bound` stays false. There is no recovery-only privilege or policy substitution after capture.

The restart adapter opts in before the interrupted session starts. After evidence: `/tmp/ymp126-restart-bounded-first-20260912/restart-inspection`. Two distinct OS PIDs, actual process exit, exact durable invocation/grant IDs and the source/executable digests are retained. The native capability is transported only over private inherited process pipes, never written to evidence. The actual inspector reads both files with an empty write scope, reports the partial totals unresolved and spends three units. All nine projected events pass the unchanged validator; reported spend is 50, reported remainder is 50, and coverage remains partial. The document acceptance and incomplete totals bytes are preserved, with zero automatic production replays.

The storage controls test missing-field default, Stop denial without admission, explicit bounded continuation for missing and partial counters, immutable captured policy across reopen, continued context and invocation denials, retained partial coverage/strict-bound rejection, and a two-connection race where reported 75 plus a 20-unit reservation permits exactly one caller. `cargo test -p ymp-storage unknown_usage -- --nocapture` passed three matching tests, including the pre-existing interruption control. Full required checks and the single-build all-case bundle follow in the final driver evidence. This is an additional correction of YMP-102 behavior requiring independent review; earlier acceptance does not cover it.
